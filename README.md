# Indian Traffic Sign Reader

PyTorch-based Indian traffic sign classification benchmark comparing a CNN trained from scratch against ResNet18 transfer learning.

> **Project status: code complete, NOT trained.** The build environment could not reach any
> verifiably licensed, publicly downloadable Indian traffic-sign dataset (see
> [DATASET.md](DATASET.md)), and I chose not to fabricate or substitute data. There are
> therefore **no results, no trained checkpoints and no accuracy numbers** in this repo. The
> pipeline is unit-tested and was exercised end to end on throwaway pixel fixtures to check
> that the code runs; those runs say nothing about real-world performance.

## Problem

Recognise a traffic sign from a photograph taken under varied lighting, distance, viewpoint
and camera conditions, as a single-label image classification task.

## Dataset

None selected yet. The brief's candidate (Datacluster Labs) publishes only a README and 17
unlabeled sample images publicly; the full dataset requires contacting the publisher and no
licence is stated. Alternatives found by search could not be verified from this environment.
Full details and the exact blockers are in [DATASET.md](DATASET.md). Class count, image count
and the split are produced by the scripts from whatever dataset you supply.

Expected input: a folder-per-class layout (`<source>/<class>/*.jpg`), or `train/` + `test/`
folders with class sub-folders. Class names are the folder names as published.

## Models

* **CNN from scratch** (`src/model_cnn.py`): 4 x [Conv3x3-BN-ReLU-MaxPool], 32-64-128-256 channels,
  global average pooling, dropout, linear layer producing logits.
* **ResNet18** (`src/model_resnet.py`): torchvision ResNet18 with ImageNet-1k weights and a new
  `fc` layer sized to the dataset. Experiment A `--mode frozen` trains only `fc` (backbone and its
  BatchNorm statistics frozen); Experiment B `--mode finetune` trains all layers.

Why: the pair isolates what pretraining buys on a small, imbalanced, domain-shifted dataset. The
outcome is measured, not assumed; if the CNN wins, the report will say so.

## Data pipeline

```
Image file -> decode (corrupt files dropped) -> RGB -> resize 96x96 -> [train only: affine,
colour jitter, blur] -> tensor + ImageNet normalisation -> DataLoader (shuffle in train)
```

Splits are class-stratified and grouped by exact/near-duplicate clusters to limit leakage.
The test split is read only by `scripts/evaluate_models.py`.

## Training defaults

AdamW, cosine LR schedule, weight decay 1e-4, batch 64, up to 30 epochs, early stopping on
validation loss (patience 7), best-validation checkpointing, seed 42, LR 1e-3 (CNN) / 3e-4
(ResNet18). Loss is plain cross-entropy; `--class-weights auto` enables inverse-frequency weights
only if the observed train imbalance ratio exceeds 3. These are defaults, not tuned values.
Every run saves its full configuration, environment and per-epoch history in `reports/metrics/`.

## Error analysis

Generated by the evaluation script, from actual test predictions: confusion matrices
(`reports/figures/confusion_matrix_*.png`), per-class precision/recall/F1 and the 10 weakest
classes (`reports/metrics/*_metrics.json`), and example grids of correct, high-confidence-wrong,
low-confidence-correct and low-confidence-wrong predictions (`error_examples_*.png`). Calibration
(expected calibration error, reliability diagrams) compares raw softmax against temperature
scaling fitted on the validation split only. No analysis is written here because no run exists.

## Demo

* `GET /` web UI: upload an image, choose CNN or ResNet18, see prediction, top-3, confidence, latency.
* `GET /health`: service status and which checkpoints exist.
* `POST /predict` (multipart: `file`, `model` = `cnn|resnet18`, optional `top_k`): JSON with
  `prediction`, `confidence` (raw softmax probability), optional `calibrated_confidence`, `top_k`.
  Errors: 400 invalid/corrupt image or model, 413 too large, 415 unsupported type, 422 malformed
  request, 503 checkpoint missing, 500 checkpoint without class mapping.

The API and UI were verified against throwaway fixture checkpoints (HTTP calls and a headless
browser). They have not been run with a trained model.

## Installation

Verified on Python 3.13.16 / Linux (CPU).

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest                   # 43 unit tests; integration tests need real data
```

Dataset setup: put an authorized dataset under `data/raw/<name>/`, then

```bash
python scripts/inspect_dataset.py --source data/raw/<name>
python scripts/prepare_dataset.py --source data/raw/<name> --name "<dataset name>"
```

## Training

```bash
python scripts/train_cnn.py                         # add --smoke-test for a 2-epoch check on a tiny real subset
python scripts/train_resnet.py --mode frozen
python scripts/train_resnet.py --mode finetune
```

ResNet18 needs the torchvision ImageNet weights (downloaded from download.pytorch.org). If they
cannot be fetched the script stops with an error; `--no-pretrained` trains from random
initialisation and is recorded as not being transfer learning.

## Evaluation

```bash
python scripts/evaluate_models.py
```

## API

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Command-line inference: `python -m src.inference path/to/image.jpg --model resnet18`.

## Limitations

Class imbalance, difficult lighting, occlusion, domain shift (a model trained on one
dataset's cameras/cities may not transfer), camera differences, and unseen sign classes (a
softmax classifier always outputs one of its known classes, there is no "unknown" option). The
near-duplicate grouping threshold and the resize-without-aspect-ratio choice are untested on
real data. Whether any of these matter here can only be said after a real run.

## Responsible use

This is a research/portfolio classifier. It must not be treated as a safety-critical
autonomous-driving component without extensive validation.
